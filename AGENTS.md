# Независимая проверка

Если в рамках задачи с изменением кода сборка уже выполнена, делегируй проверку отдельному субагенту: передай ему инструкции из [.codex/agents/quality-reviewer.md](.codex/agents/quality-reviewer.md), состав изменений и результат сборки. Дождись отчёта, разберись с существенными замечаниями и при необходимости повтори проверку затронутых изменений. Если делегирование недоступно, выполни проверку самостоятельно и сообщи об этом. Это правило не требует запускать сборку.

# Portable-дистрибутив

Для локальной сборки и запуска приложения на этом ПК используй `./publish-local.ps1`. По умолчанию скрипт публикует App и Editor в `dist/m3nuxa`, останавливает работающие процессы App и Editor и запускает tray-приложение. После каждой сборки копируй созданный дистрибутив в `\\MAIN\m3nuxa-dist`. Пути скрипта и каталога по умолчанию стабильны относительно корня проекта; сохраняй их, если ярлык ссылается на `dist/m3nuxa/m3nuxa.App.exe`. Сборка и запуск выполняются по запросу или когда нужны для проверки конкретного изменения, а не автоматически после каждой задачи.

# Среда разработки

Разработка ведётся в Windows VM Hyper-V, в том числе при удалённом подключении к Codex. UI-проверки запускай в текущей интерактивной сессии VM; для ввода и снимков экрана убедись, что сессия доступна и разблокирована.
