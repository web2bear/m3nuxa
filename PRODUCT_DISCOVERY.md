# Новый контекстный лаунчер Windows — рабочий черновик

Статус: согласованы три раунда требований, 21 октября 2026 года. Итоговая спецификация — [REQUIREMENTS.md](REQUIREMENTS.md). Этот файл сохраняет развёрнутый контекст обсуждения. Реализация не начата.

## Зачем нужен продукт

Заменить Quick Access Popup в ежедневных сценариях пользователя приложением без зависимости от AutoHotkey. Сделать редактирование меню быстрым и понятным вручную и через AI-агента.

## Подтверждено из вводных

- Технологическая основа первой версии: C#/.NET под Windows 11. LibreAutomate/Au — кандидат, окончательное использование определяется после проверки прототипом. UI-фреймворк ещё не выбран.
- Работающее в трее приложение показывает меню и предоставляет MCP-интерфейс для агента.
- Конфигурация всех меню хранится в JSON-файле и загружается в память при запуске.
- Отдельный визуальный редактор позволяет вручную менять ту же конфигурацию.
- Редактор должен быть заметно проще нынешнего. Предложена компактная двухпанельная компоновка: иерархия пунктов слева, свойства выбранного пункта справа.
- Свойства включают оформление (имя, иконка) и параметры действия; состав полей зависит от типа пункта.
- Функции «альтернативного меню» как отдельного способа задания действий предполагается убрать. Выделенные объекты, текст и другие данные становятся переменными контекста, доступными в параметрах действия.
- Для вставки переменных рассматривается простой шаблонизатор. Его синтаксис и возможности пока не выбраны.
- API для внешних программ и аппаратных лаунчеров (Mirabox N1, Elgato, Ulanzi D100H) — направление развития после первой версии.
- Вызов меню в первой версии: горячая клавиша и значок в трее.
- MCP предоставляет чтение, создание, изменение, перемещение и удаление пунктов, создание групп, проверку и общее применение конфигурации. Запуск действий через MCP не входит в первую версию.
- Открытие папки в первой версии: новое окно Проводника. Другие режимы открытия следует предусмотреть как последующее развитие.
- Действие с клавиатурой в первой версии воспроизводит одно сочетание. Последовательности сочетаний не включены в текущий объём.
- Допустимо использовать бесплатные сторонние .NET-библиотеки автоматизации без зависимости от AutoHotkey. Цель — сократить собственный код и использовать готовые реализации; надёжность выбранной библиотеки нужно проверить, она пока не подтверждена.
- Пользователь имел в виду конкретно LibreAutomate: её библиотека автоматизации должна быть рассмотрена как кандидат. Использование пока не утверждено.
- «Применить» относится ко всей редактируемой конфигурации меню: перед сохранением JSON-файла создаётся бэкап предыдущей конфигурации.
- Должна быть возможность загрузить предыдущий файл конфигурации.
- Агент через MCP самостоятельно вызывает общее «Применить» после редактирования; перед сохранением также создаётся бэкап. Подтверждение применения в UI не требуется.
- При импорте LNK извлекаются цель запуска, аргументы и рабочая папка; эти значения доступны для редактирования в свойствах созданного пункта.
- В первой версии поддерживается добавление и запуск скриптов BAT/CMD и PowerShell (PS1).
- Копирование и перемещение обрабатывают выделенные в Проводнике файлы и папки. При совпадении имён предлагается заменить, пропустить или отменить; при отсутствии выделения показывается сообщение, что переносить/копировать нечего.
- Для отправки сочетания запоминается окно, активное до вызова меню. После выбора действия этому окну возвращается фокус и в него отправляется одно настроенное сочетание клавиш.
- Все пункты образуют единое дерево меню. Любому пункту, кроме разделителя, можно назначить горячую клавишу: для действия она выполняет действие, для группы открывает её подменю без отображения родительских меню. Ограничения по числу дочерних элементов нет.
- Выделенный текст желателен в первой версии как переменная контекста, в том числе для передачи аргументом программе или скрипту, если это не требует сложной реализации. Пользователь уточнил условный приоритет этой возможности; универсальная поддержка приложений не является обязательным требованием MVP.
- Редактор и агент работают с отдельными черновиками, основанными на известной версии конфигурации. Применение устаревшего черновика не должно молча перезаписывать более новые изменения; нужно показать конфликт.
- При загрузке некорректного файла сообщить о проблемном файле и предложить исправить его либо создать дефолтную конфигурацию. Автоматического восстановления из последней рабочей версии нет.
- В редакторе предусмотрены перемещение перетаскиванием, дублирование и удаление пунктов, создание групп и разделителей. Жёсткого ограничения вложенности пятью уровнями нет.
- Всплывающее меню: компактное, с иконками и каскадными подменю, открывается у курсора и управляется мышью и клавиатурой. Поиск по пунктам не нужен, в том числе как план развития.
- Импорт и миграция из Quick Access Popup не входят в продукт.
- Шаблонизация первой версии: подстановки переменных и небольшой набор преобразований. Сложная логика остаётся во внешних BAT/CMD/PS1. Рядом с полем параметра предусмотрен выбор переменной.
- Поставка portable, конфигурация рядом с приложением в доступной для записи папке. Автозапуск включается пользователем.
- Файл конфигурации не отслеживается. Повторное чтение выполняется только при запуске или по явной команде загрузки/перезагрузки; при несохранённых правках нужно предупредить пользователя.
- Перетаскивание папки создаёт действие открытия папки. Если отдельный объект не поддерживается или LNK не удалось разобрать, показывается ошибка; остальные допустимые объекты добавляются.
- Выбранные изображения и ICO копируются в папку ресурсов приложения. Иконки EXE/DLL остаются ссылками на исходные файлы; программы и скрипты при добавлении не копируются.
- Левый клик по значку трея открывает основное меню. Правый открывает служебное меню: редактор, перезагрузка конфигурации, переключатель автозапуска, выход.
- Ошибки структуры и отсутствие обязательных полей блокируют применение. Временно недоступный путь можно сохранить с предупреждением; при попытке выполнения показывается причина недоступности.
- Скрипты по умолчанию запускаются с видимой консолью; в свойствах BAT/CMD/PS1 доступен скрытый запуск.

## Единое дерево и вызов подменю

Подтверждённая модель: одно дерево конфигурации, общее меню и прямой вызов его пунктов горячими клавишами.

- Обычный вызов открывает основное меню.
- Горячая клавиша группы открывает её содержимое как самостоятельное меню с корнем в этой группе, без предварительного показа основного или родительского меню.
- Горячая клавиша действия непосредственно выполняет действие без открытия меню.
- Это те же узлы единого дерева: копии пунктов и отдельные конфигурации для прямого вызова не создаются.
- Собственную горячую клавишу можно назначить любому пункту, кроме разделителя. Для групп нет ограничения по числу дочерних элементов.
- Горячая клавиша вызова пункта — его свойство; она отличается от действия, отправляющего настроенное сочетание в другое приложение.

Внутренние дубликаты горячих клавиш запрещены. Если сочетание недоступно из-за другой программы, нужно явно показать проблему; пункт остаётся доступным через меню.

Выделенные файлы и папки Проводника — обязательный источник контекста первой версии. Выделенный текст — желательный источник при невысокой сложности реализации; предполагается его использование в параметрах действий, в том числе при запуске программы или скрипта. До включения в обязательный объём нужно проверить возможности LibreAutomate на целевых приложениях и оценить сложность. Если необходимого контекста нет, показать причину и не выполнять действие.

Целевые приложения для проверки выделенного текста, указанные пользователем: браузер, Codex и Telegram. Конкретный браузер пока не уточнён. Наличие надёжного получения выделения в этих приложениях пока не подтверждено запуском. Допустимо временное копирование с восстановлением буфера только для действий, которым нужен выделенный текст, если проверка покажет приемлемое поведение. Существующий буфер нельзя считать текущим выделением.

Исходное окно и выделенные файлы/папки запоминаются при вызове. Для текста согласовано исключение: получать его из исходного окна после выбора действия, которому он нужен. Для прямого вызова действия горячей клавишей текст получается при этом вызове. При недоступности исходного окна или необходимого выделения действие не выполняется, показывается причина.

Переменные первой версии: выделенный текст, список выделенных путей файлов/папок, текущая папка Проводника. Преобразования: имя файла, расширение, родительская папка, кодирование текста для URL. При передаче списка файлов программе каждый путь становится отдельным аргументом; список не объединяется неявно в одну строку.

Для длительных файловых операций предусмотрены ход выполнения и отмена. При частичном сбое сообщаются успешные, пропущенные и неудачные объекты. Завершённые перемещения автоматически не откатываются.

Имя и иконка доступны у каждого действия; остальные поля соответствуют выбранной операции. Точная компоновка элементов определяется при подготовке макета.

## Основной сценарий редактора: добавить запуск перетаскиванием

Подтверждено пользователем: настройка пункта через визард мешает. Предпочтительный сценарий:

1. Перетащить EXE, файл скрипта или LNK в нужное место иерархии меню.
2. Система создаёт черновик нового пункта с иконкой по умолчанию.
3. Пользователь корректирует иконку, имя и параметры пункта в панели свойств.

Следствия для требований: порядок и вложенность должны быть видны при выборе места вставки; после создания черновика его свойства должны быть доступны без перехода в мастер настройки. Конкретное визуальное оформление позиции вставки определяется при подготовке макета.

Созданный пункт входит в редактируемую конфигурацию; применение выполняется для всего меню.

Поддерживается одновременное перетаскивание нескольких файлов. До применения доступны отмена и повтор правок. Иконку можно выбрать из EXE/DLL/ICO или файла изображения с предпросмотром.

Для LNK подтверждён импорт параметров: извлечь цель запуска, аргументы и рабочую папку в редактируемые свойства нового пункта. Полученный пункт хранит извлечённые настройки запуска. Если ярлык разобрать не удалось, сообщить об этом; остальные допустимые объекты при множественном добавлении обрабатываются.

Для скриптов первой версии подтверждены расширения BAT, CMD и PS1. После перетаскивания создаётся пункт запуска скрипта с редактируемыми параметрами. При добавлении PS1 предпочитается установленный PowerShell 7, иначе Windows PowerShell. Выбранный интерпретатор виден и редактируется в свойствах пункта. Системная execution policy автоматически не изменяется.

## Применение и восстановление конфигурации

Подтверждено пользователем:

1. Изменения накапливаются на уровне всей конфигурации меню.
2. Общая команда «Применить» сохраняет файл конфигурации.
3. Перед сохранением создаётся бэкап предыдущего файла.
4. Можно загрузить предыдущий файл конфигурации.
5. Агент может самостоятельно применить свои правки через MCP тем же общим механизмом сохранения с бэкапом.
6. Хранятся 10 последних бэкапов.
7. Старый файл открывается как черновик в редакторе; активируется общей командой «Применить».

При загрузке некорректной конфигурации сообщить о файле и предложить исправление или создание дефолтной конфигурации. Автоматического отката к последней рабочей версии нет. Дефолт содержит пустое пользовательское дерево; редактор доступен через трей. Создание дефолта выполняется по явному выбору с сохранением копии проблемного файла.

Перед применением проверяется вся конфигурация. При ошибке проверки, создания бэкапа или записи изменения не применяются: существующий файл и действующее меню не заменяются, пользователю или агенту возвращается ошибка. Успешное применение сохраняет файл и обновляет действующее меню в памяти.

Редактор и агент имеют отдельные черновики от известной версии; конфликт устаревшего черновика должен быть виден до перезаписи. Автоматическое слияние не требуется: можно сохранить свой черновик отдельно или загрузить актуальную конфигурацию. При закрытии редактора с правками предлагается применить их, отбросить или отменить закрытие.

Внешние изменения JSON автоматически не отслеживаются и не применяются. Повторная загрузка выполняется явно, с предупреждением о несохранённых изменениях.

## Предварительная модель

1. **Узел меню:** подменю, действие или разделитель. Для действия отдельно задаются отображение, тип операции и её параметры.
2. **Контекст вызова:** исходное окно и выделенные файлы/папки при вызове; текст получается из исходного окна при выполнении действия, которому он нужен.
3. **Шаблон параметра:** значение поля действия с подстановками переменных и ограниченными преобразованиями. Полноценный встроенный скриптовый язык в первую версию не включён.
4. **Одна конфигурация:** приложение, MCP и редактор используют единую модель с версиями; отдельные черновики позволяют обнаружить конфликт перед применением.
