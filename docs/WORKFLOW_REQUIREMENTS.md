# Визуальные действия и последовательности: спецификация требований

Дата: 5 ноября 2026 года. **Статус: требования согласованы пользователем 5 ноября 2026 года; готовы для подготовки реализации.**

Источник — [переданный handoff](../.codex-remote-attachments/01a1abdc-1fc4-77f1-bc4b-28cecfe6cab1/5d1dd9ba-8454-438b-9931-77b583d4515f/1-winui_workflow_codex_handoff.md): структурированный пересказ обсуждения, а не дословная стенограмма. Ниже отдельно отмечены поддержанное направление, предложения и нерешённые вопросы. При расхождении с существующими [требованиями](REQUIREMENTS.md) изменение должно быть согласовано явно; термины — в [CONTEXT.md](CONTEXT.md).

## 1. Цель и границы

Пользователь быстро настраивает распространённое действие перетаскиванием объекта и минимальным числом настроек. Если одного действия недостаточно, он добавляет шаги и располагает их в линейной последовательности. Сложные настройки раскрываются по мере необходимости; редактор скриптов не является основным интерфейсом.

**Поддержано в обсуждении:** быстрое создание действия перетаскиванием EXE, ярлыка, файла, папки, URL или PS1; простые значения по умолчанию; последовательность с перестановкой; контекстные переменные; стандартные каталоги Windows и переменные окружения.

**Уточнено пользователем:** первая версия включает существующие действия, задержку и действия с буфером обмена; при ошибке последовательность останавливается и показывает ошибку; несколько перетаскиваемых объектов создают отдельные пункты меню. Подробности действий с буфером и выполнения процессов, список доступных переменных окружения и расширенные возможности ещё не согласованы. Пункты ниже с пометкой «предложение» не следует считать принятыми решениями.

## 2. Состояние проекта на момент анализа

Это вывод по исходникам, а не результат нового запуска приложения:

- Пункт меню содержит одно `MenuAction`; существуют `OpenFolder`, `RunProgram`, `RunScript`, `SendShortcut`, `CopySelection`, `MoveSelection`, `InsertText`, `OpenItem` ([модель](../src/m3nuxa.App/ConfigModels.cs)). `OpenItem` открывает файл или HTTP(S)-адрес; папка открывается отдельным действием.
- Редактор импортирует файлы, папки, скрипты и ярлыки; URL создаёт `OpenItem`, текст — `InsertText`; несколько путей импортируются отдельными пунктами ([импорт](../src/m3nuxa.Editor/Views/MainPage.xaml.cs)). Важно сохранить существующий сценарий импорта, пока не согласовано иное.
- Контекст вызова содержит исходное окно, выбранные пути и текущую папку Проводника. Подстановки уже поддерживают `{currentFolder}`, `{selectedPath}`, `{selectedPaths}`, `{fileName}`, `{extension}`, `{parentFolder}`; `{selectedText}` и `{urlEncodedText}` пока сообщают об отсутствии данных ([исполнитель](../src/m3nuxa.App/Actions.cs)).
- Отправка клавиш и вставка текста восстанавливают фокус исходного окна и проверяют результат. Процессы запускаются через `ArgumentList`, но исполнитель не ожидает их завершения.
- Конфигурация имеет `SchemaVersion` 1, валидируется при загрузке и применении; применение сохраняет резервную копию ([хранилище](../src/m3nuxa.App/ConfigStore.cs)). MCP работает с черновиками дерева и не предоставляет запуск действий ([MCP](MCP.md)).

## 3. Функциональные требования

### 3.1. Редактирование

**WF-01. Простое действие.** Пользователь может создать пункт из поддерживаемого объекта перетаскиванием. Тип и первоначальные параметры определяются по объекту; после создания пользователь может изменить параметры. Сохранить поддержку существующих типов и работу без обязательного ввода кода.

**WF-02. Последовательность.** Пункт действия может содержать один или несколько шагов. При выполнении шаги начинают работу в порядке сверху вниз; каждый шаг хранит собственный тип и настройки. Одиночное действие остаётся простым для настройки. Действие всегда содержит хотя бы один шаг; удаление последнего шага запрещено, для удаления действия удаляется пункт дерева.

**WF-03. Изменение шагов.** Пользователь добавляет, удаляет, выбирает и переставляет шаги перетаскиванием; доступны кнопки перемещения вверх и вниз. Кнопка добавления открывает список типов действий с понятными названиями; выбранный тип добавляется сразу после выбранного шага (или в конец, если шаг не выбран) и открывается для настройки. Шаг удаляется без подтверждения и может быть восстановлен через Undo. Кнопка «Дублировать» создаёт копию шага со всеми настройками сразу после исходного и поддерживает Undo/Redo. Изменение типа существующего шага не предусмотрено: вместо этого пользователь удаляет его и добавляет новый. Параметры выбранного шага доступны в редакторе, редко используемые настройки не мешают базовому сценарию. Шаг с незаполненными обязательными параметрами допустим в черновике, но ошибка показывается рядом с настройкой и препятствует применению конфигурации. Применение, отмена изменений и Undo/Redo должны учитывать изменения последовательности вместе с остальным черновиком.

**WF-04. Доступность.** Все операции со шагами доступны без drag & drop, с клавиатуры и с понятными названиями элементов для средств доступности. Интерфейс поддерживает существующие языки приложения.

**WF-05. Несколько объектов.** При групповом перетаскивании объектов в дерево меню для каждого создаётся отдельный пункт, а не последовательность. Успешно импортированные объекты добавляются в исходном порядке; ошибки отдельных объектов показываются пользователю и не отменяют успешный импорт остальных. Перетаскивание нескольких файлов и папок в дерево создаёт для каждого отдельный пункт с начальным шагом; дальнейшие шаги добавляются кнопками. Перетаскивание объектов в список шагов в первом выпуске не предусмотрено.

**Предложение по UX:** вертикальный список карточек шагов с раскрытием параметров выбранного шага и отдельной настройкой свойств пункта; проверить прототипом до реализации полной функциональности. Перетаскивание объектов в список шагов не предусмотрено; перестановка уже созданных шагов перетаскиванием сохраняется.

### 3.2. Выполнение

**WF-06. Контекст запуска.** Для каждого вызова создаётся отдельный контекст и снимок настроек действия; последующие изменения конфигурации влияют только на новые запуски. Исходное окно, выбранные пути и текущая папка Проводника сохраняют действующую семантику момента вызова. Данные одного запуска не смешиваются с данными другого.

**WF-07. Фокус.** Действия с клавиатурой, включая вставку текста, адресуются исходному окну, даже если предыдущий шаг открыл другую программу; смена целевого окна внутри последовательности в первый выпуск не входит. Если окно недоступно или фокус не восстановлен, действие сообщает об ошибке и не отправляет ввод другому окну. Закрытие меню и восстановление фокуса не требуют от пользователя добавления служебных шагов для обычного действия.

**WF-08. Ошибки.** При ошибке последовательность останавливается и показывает ошибку с указанием пункта, шага и понятной причины; последующие шаги не выполняются. Пользователю доступна явная отмена: текущая задержка или ожидание прерывается, последующие шаги не выполняются. Отмена отличается от ошибки. Уже выполненные внешние эффекты автоматически не откатываются. Продолжение с места ошибки не предусмотрено; при повторном запуске последовательность начинается с первого шага.

**WF-09. Состав шагов.** Первая версия сохраняет восемь существующих видов действий и добавляет задержку и текстовые операции с буфером обмена: запись текста в буфер, использование текущего текста буфера в параметрах и вставку заданного текста в исходное окно. Работа со списками файлов в буфере в первый выпуск не входит. Задержка задаётся числом в миллисекундах, секундах или минутах; ноль допустим, отрицательное значение запрещено. Верхняя граница определяется при проектировании и показывается в редакторе. Текст буфера читается в момент выполнения шага, которому он необходим. Буфер является общим ресурсом Windows: пользователь или другая последовательность могут изменить его между шагами; последовательность не резервирует его целиком. Для надёжной вставки конкретного текста применяется один шаг вставки, который подготавливает буфер, выполняет вставку и при выбранной настройке восстанавливает предыдущее содержимое. При вставке предыдущее содержимое буфера восстанавливается по умолчанию; пользователь может выбрать, чтобы вставленный текст остался в буфере. Если после начала вставки буфер изменён пользователем или другой программой, новое содержимое не перезаписывается. Если буфер временно занят, приложение автоматически повторяет попытку несколько раз; если доступ получить не удалось или текст отсутствует, последовательность останавливается с понятной причиной. Отсутствие текста не подменяется пустой строкой; пустая строка в текстовом формате допустима, если её допускает параметр. Управление окнами отдельно не согласовано. Открытие файла и HTTP(S)-адреса уже поддерживается `OpenItem`.

**WF-10. Процессы.** По умолчанию после успешного запуска программы или скрипта последовательность продолжает выполнение, не ожидая завершения процесса. Для отдельного шага пользователь может включить ожидание; тогда следующий шаг не начинается до завершения процесса. Успешный запуск и успешное завершение — разные события; без ожидания результат завершения не определяется. При включённом ожидании ненулевой код выхода считается ошибкой и останавливает последовательность. При отмене ожидание прекращается, последующие шаги не запускаются, а процесс продолжает работать. По умолчанию ожидание не ограничено; в настройках шага можно включить тайм-аут. Включённый тайм-аут должен быть больше нуля; его истечение останавливает последовательность с ошибкой, не завершая процесс.

### 3.3. Контекст и параметры

**WF-11. Источники значений.** Параметры должны допускать ручное значение и доступные для данного параметра значения контекста; комбинация текста и переменных — для совместимых текстовых полей. Существующий синтаксис и его смысл сохраняются. Рядом с подходящими полями доступен выбор системного каталога или переменной окружения, вставляющий ссылку в значение; поле остаётся доступным для ручного редактирования. Конкретный синтаксис новых ключей и правила экранирования — предмет проектирования и проверки совместимости.

**WF-12. Системные каталоги.** Предоставить стандартные каталоги Windows, включая рабочий стол, документы, загрузки, изображения, музыку и видео, а также папку профиля пользователя и временную папку. Разрешать реальные системные расположения с учётом перенаправления, не выводить их конструированием пути из профиля. Хранить стабильную ссылку на каталог, а не значение пути, вычисленное на компьютере автора. Для недоступного каталога показать причину.

**WF-13. Переменные окружения.** Пользователь может явно указать имя любой переменной окружения. Для удобства предложить список распространённых переменных; при отсутствии указанной переменной сообщать об ошибке. Не записывать значения переменных в журналы по умолчанию.

**WF-14. Отсутствующий контекст.** Если необходимое значение недоступно, сообщить, какое значение требуется, и применить согласованное поведение ошибки. Нельзя считать содержимое буфера обмена выделенным текстом. Получение выделенного текста из сторонних приложений не входит в первый выпуск. Если необходимое значение отсутствует, последовательность останавливается с указанием значения и шага; запросить файл у пользователя во время выполнения не предлагается. Для существующих подстановок сохраняется действующее поведение при множественном выборе; новые поля, требующие строго один объект, сообщают об ошибке при нескольких объектах.

**WF-15. Безопасная подстановка.** Пути с пробелами и специальные символы не должны менять границы аргументов процесса; `{selectedPaths}` сохраняет правило отдельного аргумента. Подстановка данных в URL должна предусматривать корректное кодирование компонента. Секреты и содержимое буфера не должны попадать в диагностические логи по умолчанию.

### 3.4. Совместимость

**WF-16. Данные.** Существующие конфигурации должны открываться и выполняться без потери пунктов, настроек, горячих клавиш, иконок и поведения одиночных действий. После сохранения и перезапуска новые последовательности восстанавливаются в том же порядке. Версионирование и миграция должны быть явно спроектированы: текущий загрузчик отклоняет схему, отличную от 1. Сохранить защиту через резервную копию и проверку до применения. Совместимость новой конфигурации со старой версией приложения не требуется: пользователей программы пока нет. При переходе существующая конфигурация переносится автоматически: каждое действие становится последовательностью из одного шага, с сохранением его параметров и свойств пункта.

**WF-17. MCP и черновик.** Изменения модели не должны приводить к незаметной потере шагов при чтении, редактировании или применении через существующие MCP-операции. В первом выпуске MCP позволяет полноценно создавать и изменять последовательности и их шаги; отдельный инструмент выполнения не предполагается без согласования.

## 4. Сценарии приёмки

1. Пользователь перетаскивает EXE, папку, обычный файл, PS1 и HTTP(S)-адрес; создаётся соответствующее действие с понятными начальными настройками. Запись сохраняется после Apply и повторного запуска.
2. Пользователь добавляет к действию второй шаг, меняет порядок мышью и кнопками, отменяет и повторяет изменение. После применения и перезапуска порядок сохраняется, шаги запускаются в выбранном порядке.
3. В конфигурации старого формата одиночное действие открывается в редакторе и выполняется с прежними параметрами. Применение несвязанного изменения не удаляет и не меняет его.
4. Для исходного окна, ставшего недоступным до отправки клавиш, ввод не попадает в другое окно; пользователь видит ошибку с указанием шага.
5. Параметр с каталогом загрузок разрешается в действительное расположение Windows, в том числе при перенаправлении; при недоступном значении показывается понятная ошибка.
6. Выбранный файл с пробелами в имени передаётся как один аргумент, а несколько выбранных путей — отдельными аргументами согласно существующему контракту.
7. Неверный параметр шага показывает причину и номер шага, а последующие шаги не выполняются. Отмена длительного шага и уже выполненные побочные эффекты отражаются в результате.
8. Изменение другого пункта через MCP не уничтожает последовательность. Через MCP можно создать последовательность и изменить её шаги, сохранив результат после применения.

9. При перетаскивании нескольких файлов в дерево создаётся отдельный пункт для каждого файла; последовательность из них автоматически не создаётся.
10. Шаг задержки откладывает начало следующего шага на заданный интервал. Границы допустимой длительности определяются при проектировании.
11. При обычном запуске долгоживущей программы следующий шаг начинается после успешного старта, не ожидая её закрытия. Если ожидание включено для этого шага, следующий шаг не начинается до завершения процесса.

Повторный запуск того же пункта запрещён до завершения предыдущего: новый вызов не ставится в очередь, пользователю показывается сообщение и возможность открыть окно состояния; запуск разных пунктов допускается. Операции, работающие с фокусом, клавиатурой и буфером, выполняются по очереди между запусками; задержки и ожидание процессов могут выполняться параллельно. Состояние запусков и кнопка отмены доступны в отдельном небольшом окне из трея. Для активного запуска показываются название действия, текущий шаг и его номер, состояние и кнопка отмены; процент выполнения не показывается. При ошибке показывается уведомление с возможностью открыть подробности: название действия, номер и тип шага и понятную причину без содержимого буфера и значений переменных окружения. При отмене ожидающий шаг сразу удаляется из очереди; другие запуски не прерываются. Окно показывает активные и завершённые запуски текущего сеанса с результатами: успех, отмена или ошибка. История между перезапусками не сохраняется, содержимое буфера и значения переменных в неё не записываются. Доступна очистка завершённых записей, не затрагивающая активные запуски. Закрытие окна состояния не отменяет последовательности; окно можно снова открыть из трея. При выходе из приложения все последовательности отменяются, запущенные внешние программы продолжают работать, а незавершённые последовательности не восстанавливаются.

12. При переносе старой конфигурации каждое действие становится последовательностью из одного шага; настройки и свойства пункта сохраняются.
13. Для ожидаемого процесса ненулевой код выхода и истечение включённого тайм-аута останавливают последовательность. Отмена и тайм-аут не завершают внешний процесс.
14. Текст из буфера читается во время нуждающегося в нём шага; отсутствие текстового содержимого приводит к ошибке. Пустая текстовая строка допустима, если её допускает параметр.
15. Вставка по умолчанию восстанавливает прежнее содержимое буфера, но не перезаписывает изменение, сделанное после начала операции; пользователь может отключить восстановление.
16. Повторный вызов выполняющегося пункта не запускается и не ставится в очередь. Разные пункты могут выполняться одновременно, а операции с фокусом, клавиатурой и буфером выполняются по очереди; ожидание очереди отменяется без прерывания других запусков.
17. Окно запусков показывает активные и завершённые в текущем сеансе действия; его закрытие не отменяет запуски, очистка удаляет только завершённые записи, а выход из приложения отменяет последовательности.
18. Новый шаг добавляется после выбранного; дублирование копирует настройки, удаление и дублирование поддерживают Undo/Redo, а последний шаг удалить нельзя. Незавершённая настройка не позволяет применить черновик.
19. Изменение конфигурации после запуска не меняет шаги уже выполняющейся последовательности.

## 5. Вопросы для согласования

Основные продуктовые решения и спецификация подтверждены пользователем 5 ноября 2026 года. Детали реализации и проверки остаются предметом проектирования.

## 6. Вне согласованного объёма

If/Else, пользовательские переменные и передача результатов шагов следующим шагам, вызов других workflow, встроенный JS/Jint, Monaco, JSON-RPC, расширения, преобразование текста, тестирование отдельного шага и полный каталог действий являются предложениями из handoff, а не принятыми требованиями. Получение выделенного текста и обмен результатами со скриптом выходят за рамки первого выпуска и требуют отдельного согласования. Новый протокол обмена данными со скриптами в первый выпуск не входит; используются существующие параметры и, при ожидании, код выхода. Протокол JSON для внешних скриптов не является существующим контрактом.

## 7. Риски и последующая проработка

- Разделить снимок исходного контекста и значения, получаемые позднее; зафиксировать момент чтения для каждого нового источника.
- Проверить реальные drag & drop и позицию вставки, фокус, отмену и закрытие окна WinUI, а не только сохранение JSON.
- Процессы и скрипты выполняются с правами пользователя; внешний процесс сам по себе не является песочницей. Режим предупреждений не согласован.
- Для каждого поддержанного сценария определить проверяемые критерии и ожидаемый результат частичного выполнения. Создать UX-прототип до расширения каталога шагов.

## 8. Порядок реализации

Согласованный объём предназначен для одного функционального выпуска. Реализация и проверки выполняются частями: модель и перенос конфигурации; исполнитель; редактор; буфер и окно состояния; MCP и сквозная проверка. Выпуск готов после выполнения всех согласованных критериев приёмки.
