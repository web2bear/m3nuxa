# Проверка требований: дерево решений

Дата: 21 октября 2026 года. Основание: PRODUCT_DISCOVERY.md и решения пользователя в текущем обсуждении.

Статус: все три раунда завершены. Решения Q1–Q26 согласованы, включая поправки пользователя к Q3, Q9, Q11 и Q17. Открытых продуктовых вопросов в этом дереве нет. Реализация не начата.

## Подтверждённые основания

- Единое дерево с группами, действиями и разделителями; горячая клавиша доступна всем пунктам, кроме разделителей.
- Горячая клавиша действия выполняет его; горячая клавиша группы открывает только её содержимое.
- Общая команда применения сохраняет конфигурацию с бэкапом; агент также может применять её самостоятельно.
- Редактор: дерево и свойства, добавление запусков перетаскиванием, импорт параметров LNK, BAT/CMD и PS1.
- Открытие папки новым окном, запуск программы с параметрами, отправка сочетания, копирование и перемещение выделенных файлов/папок.
- Выделенный текст в браузере, Codex и Telegram желателен при простой реализации.
- Без AutoHotkey; выбраны C#/.NET и Windows 11, Au требует проверки перед окончательным выбором зависимости.

## Раунд 1: принятые решения

| ID | Ветка | Сценарий / решение | Принято пользователем |
| --- | --- | --- | --- |
| Q1 | Совместное редактирование | Пользователь меняет имя, агент одновременно перемещает пункт и применяет конфигурацию. | Раздельные черновики от известной версии; устаревший черновик нельзя применить поверх новой версии без разрешения конфликта. |
| Q2 | Полномочия MCP | Значение «создавать и редактировать пункты». | Чтение, создание, изменение, перемещение, удаление, проверка и общее применение; запуск действий через MCP не включать в MVP. |
| Q3 | Применение и восстановление | Некорректный файл конфигурации. | Сообщить о файле, предложить исправить или создать дефолтную конфигурацию. Автоматическое восстановление не требуется. Детали применения и старого файла согласованы в Q12–Q13. |
| Q4 | Контекст действия | Выделение изменилось, пока пользователь выбирал пункт. | Запоминать исходное окно и выделение при вызове; нет необходимого контекста — сообщение без выполнения действия. Для текста в Q15 согласовано исключение: получать по выбору нуждающегося в нём действия. |
| Q5 | Получение текста | Универсальный способ может временно использовать буфер обмена. | Допустить копирование с восстановлением буфера только для действия, которому нужен текст, при успешной проверке в целевых приложениях. Буфер сам по себе не считать выделением. |
| Q6 | Параметры действий | Возможности шаблонизации. | В MVP подстановки переменных и небольшой набор преобразований; сложная логика остаётся во внешнем BAT/CMD/PS1. В UI — выбор переменной рядом с полем. |
| Q7 | Конфликты горячих клавиш | Одно сочетание назначено двум пунктам или занято другой программой. | Запретить внутренние дубликаты; внешнюю недоступность явно показывать, сохраняя доступ к пункту через меню. |
| Q8 | Редактирование дерева | Дополнительные операции и глубина дерева. | Перетаскивание и перемещение пунктов, дублирование, удаление, создание групп и разделителей; предел пяти уровней пока не вводить. |
| Q9 | Отображение меню | Внешний вид, поиск и позиция открытия. | Компактное меню с иконками и каскадными подменю у курсора; управление мышью и клавиатурой. Поиск исключён, пользователь не планирует его и в дальнейшем. |
| Q10 | Технологическая основа | Выбор из рассмотренных вариантов. | Windows 11 и C#/.NET; Au — кандидат для прототипа автоматизации с последующим решением о зависимости. UI-фреймворк уточнять после макета. |
| Q11 | Переход с QAP | Нужен ли импорт существующей конфигурации. | Импорт и миграция не нужны и не планируются. |

## Раунд 2: принятые решения

| Q13 | Q3 | Бэкапы и открытие старого файла. | Хранить 10 последних бэкапов. Старый файл открывать как черновик; активировать общей командой «Применить». |
| Q14 | Q1 | Разрешение конфликта и закрытие редактора с правками. | Не делать автоматическое слияние в MVP: предложить сохранить черновик отдельно или загрузить актуальную версию. При закрытии редактора с правками предложить применить, отбросить или отменить закрытие. |
| Q15 | Q4, Q5 | Согласовать момент контекста с копированием текста по необходимости. | Окно и файлы запоминать при вызове; текст получать только после выбора нуждающегося в нём действия из исходного окна. Для текста принять это явно как исключение из правила снимка. Если окно недоступно или выделения нет, не выполнять действие. |
| Q16 | Q6 | Начальный набор переменных и преобразований. | Выделенный текст, выбранные пути файлов/папок и текущая папка Проводника; получение имени, расширения, родительской папки и кодирование текста для URL. Список файлов должен передаваться программе отдельными аргументами, а не неявно объединяться строкой. |
| Q17 | Q3 | Изменение JSON внешним редактором. | Отслеживание файла не требуется. Чтение — при запуске или явной загрузке/перезагрузке. Перед загрузкой предупредить о несохранённых правках; действуют правила версий/конфликтов. |
| Q18 | Q8 | Множественное перетаскивание, отмена и иконки. | Поддержать перенос нескольких файлов сразу, отмену/повтор правок до применения; выбор иконки из EXE/DLL/ICO и файла изображения с предпросмотром. |
| Q19 | Q10 | Поставка и автозапуск. | Portable-поставка без обязательного установщика, конфигурация рядом с приложением в доступной для записи папке; автозапуск включается пользователем. |
| Q20 | Q10 | Интерпретатор PS1. | При импорте предпочитать установленный PowerShell 7, при его отсутствии Windows PowerShell; выбранный интерпретатор виден и редактируется у пункта. Не менять системную execution policy. |
| Q21 | Файловые действия | Частичный сбой и длительные операции. | Показывать ход и отмену операции; при частичном сбое сообщать об успешных, пропущенных и неудачных объектах. Завершённые переносы автоматически не откатывать. |

Q15 уточняет правила получения контекста, но не подтверждает техническую реализацию. Надёжность получения текста в целевых приложениях ещё предстоит проверить.

## Ветки, не требующие нового продуктового решения сейчас

- Q1/Q2 → поведение конфликтов и полномочия согласованы; форма команд, ID и версий относится к техническому проектированию.
- Q3 → цикл применения, дефолт и число бэкапов согласованы; конкретные имена файлов/папок относятся к проектированию portable-поставки.
- Q4/Q5 → момент контекста и допустимость буфера согласованы; получение текста требует технического эксперимента.
- Q6 → набор переменных согласован; синтаксис и конкретный шаблонизатор выбираются при техническом проектировании.
- Q7 → правила конфликтов согласованы; проверка регистрации сочетаний — задача прототипа.
- Q8/Q9 → операции и поведение меню согласованы; окончательная компоновка и навигация проверяются на макете. Дополнительные вопросы появятся только при обнаружении реального противоречия.
- Q10 → платформа, поставка, автозапуск и интерпретатор согласованы; Au и UI-фреймворк ещё требуют технического выбора.
- Q11 → ветка импорта закрыта: миграция исключена.
