# Прототип: активация окна

Ветка `codex/window-focus-prototype` исследует выбор окна по имени процесса и необязательной части заголовка. Шаг ждёт окно до заданного времени, отклоняет неоднозначный результат и использует выбранное окно для следующих шагов ввода в текущем запуске. Прототип не предоставляет выбора окна мышью или списка окон.

Идея полей опирается на возможности QAP: просмотр списка окон с заголовком и путём процесса и получение заголовка и класса окна: https://www.quickaccesspopup.com/what-are-the-qap-features/ .

Проверка 16 ноября 2026: последовательность из меню запустила диспетчер задач и активировала его, но поиск не выполнился. Его уровень целостности был high (0x3000), уровень приложения — medium (0x2000). Первая версия ошибочно записала успешное выполнение шагов ввода. В следующую сборку добавлена проверка уровней с явной ошибкой перед вводом; эту финальную версию не удалось повторно проверить сквозным запуском через меню в текущей удалённой сессии. Проверка уровня сама по себе не подтверждает доставку ввода.

`dotnet test tests/m3nuxa.Checks/m3nuxa.Checks.csproj -c Release --no-restore`: 2/2. Проверены ожидание отсутствующего окна, отмена, доступность блокировки ввода во время ожидания и чтение уровня целостности текущего процесса. Интерактивная проверка редактора, позитивный сквозной ввод в обычное приложение и ввод с одинаковым высоким уровнем прав остаются открытыми.

Для запуска локальной portable-сборки используйте `./publish-local.ps1` с отдельным `-OutputDirectory`. Конфигурацию с новым типом шага открывайте только сборкой этой ветки. Прототип не является готовой функцией для выпуска.
