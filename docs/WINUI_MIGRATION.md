# Переход приложения запуска на WinUI 3

Меню запуска, служебное меню и окно файловых операций используют WinUI 3. Windows Forms не требуется. Трей и глобальные горячие клавиши работают через Windows API. Сообщения об ошибках и восстановлении конфигурации используют Win32 MessageBox, включая ошибки до создания XAML-корня. System.Drawing.Common сохранён для извлечения и преобразования иконок.

## Настройка оформления

`src/m3nuxa.App/LauncherMenu.xaml` содержит размер шрифта и иконок, отступы строк, ширину, скругление и фон меню. Стандартные ресурсы WinUI обеспечивают цвета светлой/тёмной темы и состояний. Изменения XAML требуют повторной публикации. Пункты, вложенность и команды по-прежнему берутся из config.json. Старый WinForms EditorForm удалён; редактор запускается отдельным процессом m3nuxa.Editor.exe.

## Поставка и проверки

`./publish-portable.ps1` публикует оба WinUI-приложения и проверяет наличие обоих PRI-файлов. Копировать нужно всю папку dist/m3nuxa.

- `dotnet run --project tests/m3nuxa.Checks -c Release`: конфигурация, иконки и обозначения горячих клавиш.
- `./tests/m3nuxa.Launcher.Checks/Run-Checks.ps1`: отдельное окно с временной конфигурацией; показ popup, открытие вложенного подменю через automation peer, закрытие/повторное открытие, пустое дерево. При наличии второго экрана меню открывается на нём. Проверка перемещает указатель мыши.
- `./tests/m3nuxa.Editor.Checks/Run-Checks.ps1`: существующие проверки редактора.

Отдельной ручной проверки требуют клики по трею, реальные глобальные сочетания, закрытие кликом снаружи, позиционирование возле краёв экранов с разным DPI, отправка сочетаний в сторонние приложения и копирование/перемещение файлов с отменой и конфликтами. Автоматическая проверка структуры меню не подтверждает эти сценарии.
