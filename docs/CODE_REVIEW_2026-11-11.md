Лимит MCP не затрагивает ручной редактор. Исходные замечания ниже сохранены как история проверки.

Дополнительно окно иконок хранит выбор до подтверждения, показывает компактное превью и поддерживает смену только цвета. Независимая проверка перед выпуском выявила влияние общего лимита черновиков на редактор; ограничение исправлено и покрыто регрессиями на 33 сеанса редактора, заполненный MCP-пул, discard и истечение срока. Мутационная проверка геометрии повторена: замена `>` на `>=` у нижней границы вложения вызывает ожидаемое падение на координате 30; исходник восстановлен.

Проверки меню и настроек также прошли после обновления ожиданий теста: отказ применения занятого сочетания проверяется как `ProtocolException(operation_failed)` действующего протокола.

Проверки перед слиянием: Release x64 и portable-публикация x64 прошли; консольные проверки и UI-проверки редактора на русском языке прошли; реальный внутренний перенос в группу и обратно прошёл. Скрипт внутреннего переноса разбирается Windows PowerShell 5.1 и PowerShell 7. Первый прогон внешнего переноса папки не прошёл: OLE получил файл, но координата попала вне дерева. Тот же сценарий прошёл на базовом коммите `8c74c9f` в отдельной рабочей копии и при повторе на текущем коде: папка, CMD и TXT добавлены в группу. Причина первого сбоя не установлена; стабильность автоматизации внешнего переноса остаётся ограничением проверки.

## Замечания

### 1. Required · Перезагрузка исчезнувшего файла очищает действующее меню

**Уже в базовом коммите.** Если файл конфигурации, ранее успешно загруженный или сохранённый, переместили либо переименовали, `Reload` создаёт пустой `AppConfig`, принимает его и повышает версию. При перезагрузке через редактор успешный результат также очищает серверные черновики. На временном файле с одной группой получены значения `before=1, version=2`, затем `reload=True, after=0, version=3`. Исходный файл при эксперименте оставался цел по новому пути. [ConfigStore.cs, строки 100–106](../src/m3nuxa.App/ConfigStore.cs#L100) · [AgentPipe.cs, строка 265](../src/m3nuxa.App/AgentPipe.cs#L265)

**Исправление и проверка.** Если хранилище ранее зафиксировало файл, его исчезновение при перезагрузке должно вернуть ошибку с путём и сохранить меню, версию и черновики. Отдельным тестом сохранить существующее поведение первого запуска до первого сохранения.

### 2. Required · Скрипт проверки внутреннего переноса перестал разбираться в Windows PowerShell 5.1

**Регрессия рабочего дерева.** Файл потерял UTF-8 BOM, а на строке 32 по-прежнему есть строковый литерал с кириллицей. На проверенной машине парсер Windows PowerShell 5.1 вернул восемь ошибок, начиная с этой строки. Скрипт завершается ещё до открытия тестового окна. PowerShell 7 разбирает тот же файл успешно. [Run-InternalDragChecks.ps1, строка 32](../tests/m3nuxa.Editor.Checks/Run-InternalDragChecks.ps1#L32)

**Исправление и проверка.** Восстановить UTF-8 BOM и проверить файл через `Parser.ParseFile` в обоих хостах. Для подтверждения самого переноса нужен отдельный прогон UI-сценария.

### 3. Required · Проверка путей выполняется синхронно в потоке интерфейса трея

**Уже в базовом коммите.** Обработчик канала ставит запрос в UI-контекст. При сохранении он валидирует черновик, затем хранилище повторяет ту же валидацию. Для поддерживаемых действий с буквальным путём каждая валидация может обратиться к файловой системе через `File.Exists` и `Directory.Exists`. Если в меню есть недоступный сетевой ресурс, поток интерфейса ждёт ответа файловой системы. У редактора при этом уже через три секунды может истечь ожидание ответа, хотя сервер продолжает операцию. Цепочка подтверждена по коду, длительность ожидания на недоступном UNC-пути не измерялась. [AgentPipe.cs, строки 155 и 311–315](../src/m3nuxa.App/AgentPipe.cs#L155) · [ConfigStore.cs, строка 119](../src/m3nuxa.App/ConfigStore.cs#L119) · [Проверка пути, строка 362](../src/m3nuxa.App/ConfigStore.cs#L362) · [EditorPipeClient.cs](../src/m3nuxa.Editor/EditorPipeClient.cs#L81)

**Исправление и проверка.** Отделить обязательную проверку структуры от сбора предупреждений о путях. Собирать предупреждения один раз вне UI-потока, а версию черновика проверять непосредственно перед записью. В тесте задержать проверку пути и убедиться, что трей обрабатывает другие события и редактор получает фактический результат сохранения.

### 4. Required · Брошенные MCP-черновики остаются в памяти

**Уже в базовом коммите.** Каждый HTTP-вызов `begin` получает новый ID и сохраняет копию полной конфигурации в словаре процесса трея. Успешное применение удаляет только применённый черновик. После разрыва работы клиента его копия остаётся до успешной перезагрузки через канал либо завершения процесса. В опубликованном наборе MCP-инструментов нет операции отмены. Память растёт с числом незавершённых сеансов и размером меню. [McpHttpServer.cs, строка 90](../src/m3nuxa.App/McpHttpServer.cs#L90) · [AgentPipe.cs, строки 253, 265 и 316](../src/m3nuxa.App/AgentPipe.cs#L253)

**Исправление и проверка.** Предусмотреть явное освобождение и ограничить срок хранения неактивных черновиков. Проверить с управляемыми часами, что брошенный черновик освобождается, а соседний активный сеанс продолжает редактирование.

### 5. Optional · Пустая область дерева означает разные места вставки в OLE и XAML

**Уже в базовом коммите, затронуто текущей переработкой.** При внешнем переносе в пустое место под строками дерева обработчик OLE использует текущий выбор. Если выбрана группа, элемент попадёт в неё. Обработчик XAML для той же зоны выбирает корень. Численная геометрия может вернуть правильную зону в обоих случаях, хотя результат импорта различается. Вывод по двум обработчикам, без ручного воспроизведения. [Обработчик OLE](../src/m3nuxa.Editor/Views/MainPage.xaml.cs#L1144) · [Обработчик XAML](../src/m3nuxa.Editor/Views/MainPage.xaml.cs#L1474)

**Исправление и проверка.** Определить назначение зоны `Empty` в одном месте и проверить итогового родителя элемента для обоих способов переноса при выбранной группе.
