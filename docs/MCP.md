# Подключение MCP

MCP HTTP-сервер встроен в `m3nuxa.App.exe`. Включите пункт **MCP HTTP-сервер** в контекстном меню трея и подключите MCP-клиент к `http://127.0.0.1:58342/mcp` через Streamable HTTP. Пункт **Копировать адрес MCP** помещает адрес в буфер обмена. Повторное нажатие **MCP HTTP-сервер** выключает сервер; состояние сохраняется в `mcp-http.json` рядом с приложением и восстанавливается при запуске. Сервер слушает только локальный адрес.

Если клиент раньше запускал `m3nuxa.Mcp.exe` через stdio, замените эту настройку на HTTP-адрес выше.

Доступны инструменты `read`, `begin`, `create`, `update`, `set_steps`, `move`, `delete`, `discard`, `validate`, `apply`. `begin` возвращает `draftId`; передавайте его всем операциям с черновиком. `apply` проверяет базовую версию и создаёт резервную копию перед сохранением. Инструмента выполнения пользовательских действий нет.

`discard` освобождает ненужный черновик без сохранения. Одновременно поддерживаются до 32 MCP-черновиков; при заполнении лимита `begin` возвращает `draft_limit`. MCP-черновики без обращений более 30 минут удаляются при следующем запросе; обращение к удалённому черновику возвращает `draft_not_started`. Лимит MCP не ограничивает открытие ручного редактора.

## Последовательности действий

Пункт вида `Action` содержит непустой упорядоченный список `Steps`. Инструмент `set_steps` заменяет список целиком: передайте `draftId`, `id` пункта и массив `steps` в нужном порядке. Так можно добавить, изменить, переставить или удалить шаги; пустой список и `null` вместо шага запрещены. Данные остаются в черновике до `apply`, а `validate` проверяет параметры каждого шага.

Пример аргументов `set_steps`:

```json
{
  "draftId": "идентификатор-черновика",
  "id": "идентификатор-пункта",
  "steps": [
    { "Kind": "InsertText", "Text": "Привет" },
    { "Kind": "Delay", "DelayMilliseconds": 500 },
    { "Kind": "SetClipboardText", "Text": "готово" }
  ]
}
```

`update` меняет свойства пункта, сохраняя его идентификатор, вид, шаги и дочерние пункты. Менять шаги можно только через `set_steps`, а дочерние пункты — через `create`, `move` и `delete`. Передача отличающихся непустых списков шагов или дочерних пунктов в `update` вызывает ошибку; пропущенные или пустые списки сохраняют существующие значения. Вид пункта через `update` не меняется.

Для `RunProgram` и `RunScript` опция `WaitForExit` включает ожидание, `TimeoutMilliseconds` задаёт положительный тайм-аут либо `null` для ожидания без ограничения. `DelayMilliseconds` — неотрицательное число миллисекунд. Для шага `PasteText` параметр `RestoreClipboard` по умолчанию равен `true`. Чтение буфера в шаблонах параметров и доступные подстановки описаны в руководстве пользователя по мере реализации.
