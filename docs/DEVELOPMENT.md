# Разработка и проверки

## Отладка в Rider

Откройте `m3nuxa.sln` с конфигурацией Debug x64. Для запуска обоих компонентов с отладочными символами выполните:

```powershell
.\tools\Start-Debug.ps1
```

Скрипт останавливает работающие App и Editor (включая portable-версию) и публикует Debug x64 с PDB в `dist/debug/`. Конфигурация меню и логи лежат в этой же папке отдельно от `dist/m3nuxa/`. Редактор переносится на дополнительный экран, если он подключён.

В Rider выберите **Run → Attach to Process** и подключитесь к `m3nuxa.App.exe` или `m3nuxa.Editor.exe`. MCP встроен в App и включается из меню трея.

Для отдельного запуска используйте `-Component App` (только трей) или `-Component Editor` (редактор вместе с необходимым ему App). Режим `-Component None` только подготавливает Debug-сборку, без запуска процессов.

## Диагностика

На этапе разработки приложение и редактор записывают события запуска, ошибок и обмена с редактором в `logs/m3nuxa-dev.log` внутри папки запуска: `dist/m3nuxa/` для portable или `dist/debug/` для Debug. Содержимое конфигурации в лог не записывается.

## Проверки и ограничения

Проверка подписей WinUI-дерева после переноса действия в группу, выбора пунктов, переименования, отмены и повтора: `./tests/m3nuxa.Editor.Checks/Run-Checks.ps1`. Для реальных нажатий требуется установленный `winapp` CLI и доступный рабочий стол. Проверка открывает отдельное окно на дополнительном экране, явно передаёт ему фокус и не применяет пользовательскую конфигурацию. Если приложение в трее не запущено, создаётся отдельная тестовая сборка, которая останавливается после проверки.

Получение выделенного текста из сторонних приложений пока не включено. Переменная `selectedText` выдаёт явную ошибку отсутствующего контекста. Поведение UI, выделения Проводника, возврата фокуса и открытия нового окна Проводника требует проверки на целевой Windows 11.

Проверки конфигурации и настроек:

```powershell
dotnet run --project .\tests\m3nuxa.Checks\m3nuxa.Checks.csproj
```

Проверки меню и окна настроек:

```powershell
.\tests\m3nuxa.Launcher.Checks\Run-Checks.ps1
```

После запуска обычного редактора для визуальной проверки выполните `./tools/Move-TestWindow.ps1`: при наличии второго экрана окно должно находиться в его рабочей области. Для другого процесса передайте `-ProcessName`. Автоматическое окно `m3nuxa.Editor.Checks` выбирает дополнительный экран самостоятельно.

## Публикация

`publish-portable.ps1` публикует App и Editor в общую папку, проверяет наличие EXE и PRI, удаляет устаревший отдельный MCP EXE и лишние языковые ресурсы. В поставке оставляются ресурсы `en-US` и `ru-RU`. Подробности перехода на WinUI — в [WINUI_MIGRATION.md](WINUI_MIGRATION.md).
